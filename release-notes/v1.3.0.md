## v1.3.0 — Voltage / frequency sensors and opt-in current / PF / VAR

This release expands what the integration surfaces from each samples POST. The hub already sends voltage, frequency, current, power factor, and reactive power on every payload — 1.3.0 actually exposes them.

### What's new

- **Per-phase Voltage and Frequency sensors** are now created automatically — one pair per ADE chip with a real voltage reference. No opt-in required.
  - Hub variants that wire voltage only to chips A and B → 2 pairs.
  - Hub variants that wire all four chips, and Lite 2-chip hubs → 4 pairs / 2 pairs respectively.
- **Three new opt-in sensors per circuit**, each behind its own checkbox in the options flow (defaults OFF):
  - **Show Current** — Amps per circuit.
  - **Show Power Factor** — signed −1…1 per circuit.
  - **Show Reactive Power** — VAR per circuit.
- **Power on chips C and D no longer sticks at 0 on hubs that don't wire voltage there.** When a chip's voltage reads below 10 V the integration substitutes `w = V_neighbor × I / 3600` (chip C piggybacks on phase A, chip D on phase B), so loads on those circuits report a usable apparent-power approximation. Hubs that wire all four chips are unaffected — the substitution is gated on the actual per-chip voltage reading.

### Fixes

- The options-flow circuits step no longer overwrites the entire per-device options entry on save, so settings written by other surfaces (e.g. the Live Power Readings switch) survive a circuits-form save.

### Upgrade notes

- Voltage and Frequency sensors appear automatically on the next POST. No action required.
- Tick the new **Show Current / Show Power Factor / Show Reactive Power** checkboxes in the options flow if you want those quantities exposed; sensors are created on the integration reload.
- The new live readings are persisted alongside power, so a planned reload comes up with last-known values rather than flipping sensors to `unavailable` until the next POST.

### Caveats

- The chip-C/D power approximation is unsigned (current is RMS), so bidirectional circuits on substituted chips can only register consumption, not export.
- Toggling a Show-… checkbox OFF leaves orphaned `unavailable` entities in the entity registry until you delete them manually — the standard cost of removing entities in HA.
